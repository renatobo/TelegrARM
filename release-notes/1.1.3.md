## New Features

- Added developer hooks: the `telegrarm_should_enqueue` and `telegrarm_message_text` filters, and the `telegrarm_delivery_sent` and `telegrarm_delivery_abandoned` actions.
- Added suggested privacy policy text under Settings > Privacy, naming Telegram as the recipient of member data.
- Added a Rescan button to the ARMember field discovery. Discover fields now reuses the ten-minute cache.

## Improvements

- Credential and permission keys such as `user_pass`, `session_tokens`, and `*_capabilities` are rejected when the field mapping is saved and are never included in a message, even if already stored.
- The bot token field is disabled when `TELEGRARM_BOT_TOKEN` is defined in `wp-config.php`, so a saved value can no longer be silently overridden.
- Deactivating the plugin now clears its cron events and deletes any queued payloads, instead of leaving member data in the options table.
- Uninstall now cleans every site on a multisite network.
- The avatar link is validated without a DNS lookup, so a profile save no longer waits on resolving a member-supplied host.
- The version marker is autoloaded, removing one database query per request.
- Translations load on `init`, and the unused `Domain Path` header was removed.
- The admin test message returns HTTP 502 when Telegram itself rejects the request.
- GitHub Actions in all workflows are pinned to commit SHAs.

## Bug Fixes

- Fixed profile-update notifications never firing on ARMember Lite. They relied on `arm_update_profile_external`, which only ARMember Pro fires. TelegrARM now listens to the profile-save hooks both editions fire, and still ignores registrations and administrator edits.
- Fixed `user_login`, `user_email`, and other account fields never appearing in new-user messages. They live in the users table rather than user meta and are now included, while `user_pass` and `user_activation_key` never are.
- Fixed message lines following the order the data happened to be stored in. They now follow the mapping order, so rearranging fields in the mapping builder changes the message as intended.
- Fixed every settings notice appearing twice on the settings page.
- Fixed a successful test message reporting "Unknown Telegram API error." as the Telegram description.
- Fixed ARMember's login-form "Remember me" checkbox being offered as a mappable field in field discovery.
- Fixed notifications being dropped when a mapped field contained a named HTML entity such as `&nbsp;`. Telegram rejects those entities, so every value is now fully encoded.
- Fixed checkbox and multi-select fields appearing as serialized PHP in new-user messages and being omitted from profile-update messages. They are now shown as comma-separated lists.
- Fixed contact cards failing when the member had no first name. The login name is used instead.
- Fixed a failed schedule suppressing an identical retry for one minute.
- Fixed uninstall leaving pending delivery events in the cron schedule. Those events carry a ticket argument, which the previous cleanup call did not match.

## Compatibility

- No settings or data migration. Mappings that contain a credential key keep working, but that key is skipped when messages are built and removed the next time settings are saved.
- Plugins that filtered `esc_html` output no longer affect Telegram message text.
